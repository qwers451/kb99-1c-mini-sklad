## Шаги воспроизведения

### А. Установка модуля интеграции (объединение конфигураций)

Требования:
- Конфигурация на управляемых формах. Модуль ставится в неё как отдельная подсистема.
- Рекомендуемая платформа 8.3.14 и выше. У нас 8.3.27, подходит.

Варианты использования:
- **Отдельная база** с интеграцией. Документы реализации выгружаются в неё и загружаются обратно.
- **Встраивание в рабочую конфигурацию.** Документы ВСД создаются на основании существующих. Этот вариант рекомендован.

Порядок действий:
1. Скачать актуальную версию интеграции. Сделать резервную копию рабочей базы, развернуть копию и открыть её в Конфигураторе.
2. Для типовой конфигурации на поддержке: **Конфигурация → Поддержка → Настройка поддержки**, включить режим «возможность изменения». Затем выделить корень дерева и убедиться, что режим позволяет ставить интеграцию без изменения типовых объектов.
3. **Конфигурация → Сравнить, объединить с конфигурацией из файла**, указать файл интеграции.
4. Снять все отметки в дереве. Выбрать **Действия → Отметить по подсистемам файла**.
5. В окне подсистем снять «Интеграция_кб99_Ветис», отметить «кб99_ВСД» и нажать **Установить**.
6. Если в базе нельзя использовать расширения, дополнительно отметить общий модуль «кб99_ВСД_Переопределения».
7. Нажать **Выполнить**. На окно «Неразрешимые ссылки» ответить **Продолжить**. Дождаться конца объединения, нажать **ОК** и принять изменения структуры данных.
8. После проверки в копии сохранить конфигурацию в `.cf`, а расширения в `.cfe`.
9. Перенос в рабочую базу:
   - сделать резервную копию `.dt`;
   - снова выполнить «Сравнить, объединить» с сохранённым `.cf`, отметив только «кб99_ВСД»;
   - если модуль «кб99_ВСД_Переопределения» дорабатывался, отметить и его;
   - нажать **Выполнить** и принять изменения структуры.
10. Для «1С:Управление нашей фирмой» отдельно подключить расширение из Redmine kb99. Затем подключить расширение с переопределёнными функциями.

### Б. Настройка параметров интеграции

Параметры задаются в разделе **кб99 ВСД → Параметры интеграции**. Порядок вкладок ниже совпадает с порядком первой настройки.

1. **Подключение** — реквизиты доступа:
   - Реквизиты Ветис.API выдаёт Россельхознадзор по заявке хозяйствующего субъекта (ХС) после регистрации в реестре РСХН:
     - **Login**, **Password**;
     - **APIKey** — ключ информационной системы в шлюзе Ветис.API;
     - **IssuerID** — уникальный идентификатор.
   - **Логин инициатора** и **Логин ветврача** — личные логины пользователей веб-интерфейса «Меркурия». По ним проверяются полномочия при работе с документами.
   - **Код лицензии** нужен только для продуктивного контура. Для тестового контура его не заполняют.
   - Нажать **Сохранить параметры**, затем **Выполнить**. Это начальная загрузка данных и классификаторов.
2. **Параметры по умолчанию** — после загрузки данных заполнить значения по умолчанию, в том числе цель перевозки, и нажать **Сохранить параметры**.
3. **Документы** — правила формирования ВСД:
   - *Входящие ВСД:*
     - сверка количества с приходной накладной;
     - заполнение термических условий;
     - проверка даты изготовления при гашении;
     - контроль документа происхождения;
     - загрузка и контроль лабораторных исследований.
   - *Транспортные ВСД:*
     - **Имя реквизита [Грузополучатель] в Реализации** — по нему документ отгрузки связывается с площадкой получателя;
     - **Номер автомобиля (по умолчанию)**;
     - **Имя реквизита [Количество]** и **Коэффициент пересчёта количества в ВСД**;
     - фильтр реализаций по складу площадки;
     - разделение ВСД по термическим условиям;
     - пропуск товаров без соответствий;
     - добавление строки с нехватающим количеством;
     - автоустановка соответствий;
     - проверки упаковки, формата номера автомобиля и сроков годности;
     - показ просроченных партий;
     - разрешение замены продукции.
   - *Уровни упаковки в ВСД2:* имя реквизита количества мест, номер уровня, форма упаковки.
   - *Партии:*
     - заполнение по сериям;
     - реквизит сортировки и сортировка по убыванию (LIFO);
     - контроль остатков партий по регистру «ОстаткиПартийВСД» с заданной даты.
   - *Инвентаризация:* причина расхождения, описание несоответствия, число строк списания (рекомендуется до 1000, оптимально 250).
   - *Аннулирование ВСД:* причина аннулирования по умолчанию.
4. **Производство** — нужно только производителям:
   - завершение производственных транзакций;
   - подбор сырья по спецификациям;
   - коэффициент пересчёта;
   - префикс незавершённого производства;
   - контроль баланса сырья и продукции с допустимым процентом расхождения;
   - построчная разбивка производства;
   - внутренние перемещения между своими ХС и площадками.
5. **Инициализация**:
   - кнопка **Загрузить** — то же, что «Выполнить» на вкладке «Подключение»;
   - загрузка отдельных классификаторов;
   - обновление справочников при переходе с API 1.0 на 2.0;
   - перенос параметров из хранилища настроек в регистр (с версии 2.8.16).
6. **Сервис** — служебные операции:
   - загрузка партий за период со смещением (ВетИС отдаёт не более 1000 элементов на запрос);
   - регистрация и получение продукции по площадке;
   - соответствия по умолчанию;
   - регистрация ХС и площадок, получение GUID по ИНН;
   - загрузка ВСД по периоду, статусу и типу;
   - запросы условий перевозки;
   - очистка старых запросов.

### В. План подключения «Мини-Склада»
1. Получить в Россельхознадзоре тестовые реквизиты Ветис.API: Login, Password, APIKey, IssuerID. Получить логины пользователей «Меркурия».
2. Развернуть копию базы «Мини-Склад» и выгрузить её в `.dt`. Объединить конфигурацию с файлом интеграции, отметив подсистему «кб99_ВСД». Конфигурация собственная и не на поддержке, поэтому шаг с настройкой поддержки не нужен.
3. Сопоставить наши объекты с параметрами интеграции:

   | Параметр интеграции | Объект «Мини-Склада» |
   |---|---|
   | Документ отгрузки | `Документ.Реализация` |
   | Имя реквизита [Грузополучатель] в Реализации | `Контрагент`: у нас один контрагент — один адрес |
   | Имя реквизита [Количество] | `Количество` табличной части «Товары», коэффициент пересчёта 1 |
   | Приходная накладная для сверки входящих ВСД | `Документ.Поступление` |
   | Соответствия «номенклатура 1С ↔ Продукция_Элемент» | `Справочник.Товары` |

4. Заполнить вкладку «Подключение» без кода лицензии (тестовый контур), нажать «Сохранить параметры» и «Выполнить». Затем по очереди заполнить «Параметры по умолчанию» и «Документы». Вкладку «Производство» не трогать, так как производства нет.
5. На вкладке «Сервис» получить GUID хозсубъекта по ИНН, загрузить площадки и продукцию площадки, затем установить соответствия товаров.

## Что должно получиться
- Скрин 1: окно «Сравнение, объединение» с отмеченной подсистемой «кб99_ВСД» (снято «Интеграция_кб99_Ветис»).
- Скрин 2: в командном интерфейсе появилась подсистема «кб99 ВСД» с командой «Параметры интеграции».
- Скрин 3: вкладка «Подключение» с заполненными Login, APIKey, IssuerID (пароль скрыт) и сообщением об успешной начальной загрузке.
- Ожидаемый результат/данные:
  - конфигурация объединена без ошибок, изменения структуры приняты;
  - классификаторы «Меркурия» загружены;
  - параметры сохранены, с версии 2.8.16 они лежат в регистре;
  - документы «Реализация» видны в групповой обработке оформления ВСД.

## Замеченные ошибки/ограничения
- Самого файла интеграции и тестовых реквизитов Ветис.API у меня нет: их выдают kb99 и Россельхознадзор. Поэтому пункт выполнен как изучение и план. Установка в базу не проводилась.
- На странице «Параметры по умолчанию» поля показаны только скриншотом, текстом они не описаны.
- Объединение меняет основную конфигурацию. Работать нужно только в копии базы и с резервной копией `.dt`.
- Код лицензии нужен только в продуктивном контуре. Перед переходом с теста на прод его нужно получить заранее.
- ВетИС отдаёт не более 1000 элементов за запрос. Партии за большой период нужно загружать в несколько запросов со смещением.
